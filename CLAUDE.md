# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`atRutils` is an R package of shared data-management utilities for ATR Consulting, published to GitHub as `atrcodebase/atR_utils` and installed by users via `pak::pak("atrcodebase/atR_utils")`.

It is still close to its `usethis`-generated skeleton: one source file, one exported function. `DESCRIPTION` metadata is filled in and `devtools::check()` passes clean. Expect to be adding structure, not just code.

## Commands

Run from the package root. R 4.5.2, devtools 2.4.6, roxygen2 7.3.3, testthat 3.3.2 are installed.

```sh
Rscript -e 'devtools::load_all()'          # load package into a session (fast iteration)
Rscript -e 'devtools::document()'          # regenerate NAMESPACE + man/ from roxygen comments
Rscript -e 'devtools::test()'              # run all tests
Rscript -e 'devtools::test(filter = "parseDateTime")'   # run one test file (matches tests/testthat/test-<filter>.R)
Rscript -e 'devtools::check()'             # full R CMD check — the gate before publishing
Rscript -e 'devtools::install()'           # install locally
```

`devtools::check()` is the real lint for an R package; there is no separate linter configured.

## Conventions this package is set up for

- **NAMESPACE is generated.** Never edit it by hand — add `#' @export` roxygen tags and run `devtools::document()`.
- **Roxygen markdown is on** (`Roxygen: list(markdown = TRUE)` in DESCRIPTION), so roxygen comment blocks take markdown syntax.
- **testthat edition 3** (`Config/testthat/edition: 3`). Test files go in `tests/testthat/` as `test-<topic>.R`; `tests/testthat.R` is boilerplate and should not be modified.
- **Dependencies belong in DESCRIPTION, not in `library()` calls.** Add with `usethis::use_package()` and call qualified (`lubridate::as_datetime()`). Never `library()` at the top level of a file in `R/`.
- Internal helpers are prefixed with `.` and carry no roxygen block, so they stay out of `NAMESPACE` and `man/`.

## Existing code

[R/parseDateTime.R](R/parseDateTime.R) holds `parse_to_datetime()`, the package's only export: a vectorized parser for mixed-format dates returning `POSIXct`.

**The central invariant is anchored matching.** `strptime()` does not require a format to consume the whole string, so `"%Y-%m-%d"` matches the prefix of `"15-01-2024"` and silently returns year 15. Every candidate format is therefore paired with a fully anchored regex generated by `.fmt_to_regex()`, and a format is only attempted on strings its regex matches end to end. **Any format added to `.format_table()` must go through this machinery** — adding a bare `strptime` call reintroduces prefix-matching corruption. New format tokens need an entry in `.STRPTIME_RX`.

The parser is a mask pipeline: each stage claims elements it resolves and clears them from `pending`. Order matters and is load-bearing:

1. **Compact `yyyymmdd`** — must precede numeric, which would otherwise read `20240115` as Unix seconds.
2. **Numeric** — Unix seconds vs. Excel serial days, split at `> 100000` (or negative → Unix). Excel origin is `1899-12-30`; the conversion multiplies out days so fractional serials keep their time.
3. **ISO 8601** — `T` or space separator, optional sub-seconds and offset; delegated to `lubridate::as_datetime()`.
4. **JavaScript `Date.toString()`**.
5. **Anchored format loop** — year-first layouts first (unambiguous), then the ambiguous day/month pair, then month-name layouts. Date format varies slowest across the time-variant cross product so the day/month choice applies consistently whether or not a time is attached.

Unlike earlier versions, a stage that matches an element's *shape* but fails to parse it leaves that element pending, so it can still be resolved downstream.

**Day/month order is resolved per element, not per call.** `.resolve_dayfirst()` returns a logical *vector*, so one input vector can hold both conventions. A value is self-evident when one of its first two components exceeds 12 (`"25/12/2024"` can only be day-first) and is decided from its own digits. Only values with both components `<= 12` consult the column-level vote, which tallies the self-evident values weighted by occurrence count and falls back to day-first on a tie, warning as it does so. Stage 5 therefore runs the format loop once per convention over disjoint subsets. `dayfirst = TRUE/FALSE` overrides only the vote, never the self-evident values.

Two things to preserve when editing: parsing runs inside `.with_c_time_locale()` so `%b`/`%B`/`%p` work regardless of the machine's `LC_TIME`, and string parsing runs over `unique()` values with results expanded via `match()` — the fast path that keeps large columns cheap (200k rows in ~0.06s). The dedup is why occurrence counts are passed to `.parse_strings()` as `weights`: without them the day/month vote would count distinct strings rather than rows, and a single typo could outvote a thousand consistent values.

`tests/testthat/test-parseDateTime.R` opens with regression tests for specific historical corruption bugs (day-first truncation, dropped time, `yyyymmdd` misread, NA-subscript crash). Keep those cases when refactoring.
